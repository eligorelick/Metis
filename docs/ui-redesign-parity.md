## Financial and operational boundary

No investment engine, accounting convention, prompt, source-selection rule or report schema semantic change is part of the UI migration. Job authority, request fencing, retry eligibility and pipeline semantics remain existing production contracts; the redesigned client can attach to an existing server-owned run on reload. Any change outside presentation/configuration/tests must be separately justified and reviewed. The final diff audit must name every such file rather than assert this boundary from intent.

Runtime paths, provider credentials, report bytes and job queues in the user's installation are outside the preview. Git branch isolation does not isolate the per-user credential store; the preview runner must explicitly isolate its discovery root too.
